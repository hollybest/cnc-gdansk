# Задача: опубликовать сайт CNC Gdańsk на GitHub Pages со своим доменом

Ты работаешь в папке с готовым статическим сайтом. Твоя задача — опубликовать его на GitHub Pages и привязать домен пользователя. Сайт уже полностью готов: **не меняй тексты, вёрстку, стили и картинки**. Меняй только то, что прямо указано ниже.

## Что лежит в папке

| Файл | Назначение |
|---|---|
| `index.html` | Главная страница (польский язык). Форма заявки открывает WhatsApp, серверная часть не нужна. |
| `images/` | 7 изображений `.webp`, на них ссылается `index.html`. |
| `404.html` | Страница «не найдено». |
| `favicon.svg` | Иконка сайта. |
| `robots.txt`, `sitemap.xml` | Для поисковиков. |
| `CNAME` | Домен для GitHub Pages. |
| `.nojekyll` | Отключает Jekyll, чтобы GitHub отдавал файлы как есть. Не удалять. |
| `AGENTS.md` | Этот файл с инструкциями. |

Во всех файлах стоит метка `__DOMAIN__`. Её нужно заменить на домен пользователя.

## Шаг 0. Узнай домен

Если пользователь не назвал домен в сообщении — спроси и не продолжай без ответа.

Приведи домен к виду без протокола, без `www.` и без слэша. Например:
`https://www.cncgdansk.pl/` → `cncgdansk.pl`. Дальше этот домен называется `DOMAIN`.

## Шаг 1. Подставь домен

Замени `__DOMAIN__` на `DOMAIN` в файлах `index.html`, `CNAME`, `robots.txt`, `sitemap.xml`.

Проверь, что метка нигде не осталась:

```bash
grep -rn "__DOMAIN__" --exclude=AGENTS.md . && echo "ОШИБКА: метка осталась" || echo "OK"
```

Файл `CNAME` должен содержать ровно одну строку — домен — и больше ничего.

## Шаг 2. Проверь инструменты

```bash
git --version
gh --version
gh auth status
```

- Если `gh` не установлен — скажи пользователю установить GitHub CLI (macOS: `brew install gh`, Windows: `winget install --id GitHub.cli`, Linux: https://cli.github.com) и подожди.
- Если `gh auth status` показывает, что вход не выполнен — попроси пользователя самому выполнить `gh auth login` (вход интерактивный, через браузер). **Никогда не проси у пользователя пароль или токен и не вписывай их в файлы.**

## Шаг 3. Создай репозиторий и загрузи сайт

Имя репозитория по умолчанию — `cnc-gdansk` (если пользователь назвал другое — используй его).

```bash
git init -b main
git add .
git commit -m "Strona CNC Gdańsk"
gh repo create cnc-gdansk --public --source=. --remote=origin --push
```

Репозиторий должен быть **публичным**: на бесплатном тарифе GitHub Pages работает только с публичными репозиториями.

Если репозиторий с таким именем уже существует — не удаляй и не перезаписывай его, спроси пользователя.

## Шаг 4. Включи GitHub Pages и привяжи домен

```bash
OWNER=$(gh api user --jq .login)
REPO=cnc-gdansk

gh api -X POST "repos/$OWNER/$REPO/pages" -f "source[branch]=main" -f "source[path]=/"
gh api -X PUT  "repos/$OWNER/$REPO/pages" -f cname="DOMAIN"
gh api "repos/$OWNER/$REPO/pages"
```

Если первая команда отвечает, что Pages уже включены, — это не ошибка, переходи дальше.

Проверь, что сайт открывается по временному адресу (публикация занимает 1–2 минуты):

```bash
curl -sI "https://$OWNER.github.io/$REPO/" | head -n 1
```

## Шаг 5. Выдай пользователю настройки DNS

Изменить DNS ты не можешь — это делается в панели регистратора домена. Покажи пользователю ровно эти записи:

| Тип | Имя / хост | Значение |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `OWNER.github.io` (подставь реальный логин) |

И предупреди: другие A-записи и AAAA-записи для `@` (например, страницу-заглушку регистратора) нужно удалить, иначе сайт будет открываться через раз.

## Шаг 6. После того как пользователь настроил DNS

Проверь, что DNS указывает на GitHub:

```bash
nslookup DOMAIN
nslookup www.DOMAIN
gh api "repos/$OWNER/$REPO/pages/health"
```

Обновление DNS занимает от нескольких минут до 24 часов. Если записи ещё старые — скажи пользователю подождать и повторить проверку позже. Не меняй настройки в попытке «ускорить».

Когда DNS указывает на GitHub и GitHub выпустил сертификат, включи HTTPS:

```bash
gh api -X PUT "repos/$OWNER/$REPO/pages" -F https_enforced=true
```

Если команда отвечает, что сертификат ещё не готов, — подожди 15–30 минут и повтори.

## Шаг 7. Финальная проверка

```bash
curl -sI "https://DOMAIN/" | head -n 1
curl -sI "https://DOMAIN/images/hero-frezarka.webp" | head -n 1
curl -sI "https://DOMAIN/sitemap.xml" | head -n 1
curl -sI "https://www.DOMAIN/" | head -n 3
```

Ожидаемо: первые три — `200`, адрес с `www` перенаправляет на основной домен.

Сообщи пользователю итог: адрес сайта, ссылку на репозиторий и что ещё осталось сделать (если что-то осталось).

## Как обновлять сайт потом

Пользователь присылает новый `index.html` → положи его вместо старого, **сохранив** блок `<link rel="canonical">`, Open Graph и `application/ld+json` в `<head>` с реальным доменом, затем:

```bash
git add .
git commit -m "Aktualizacja strony"
git push
```

## Чего не делать

- Не менять содержимое и дизайн сайта без прямой просьбы пользователя.
- Не удалять `.nojekyll`, `CNAME` и папку `images/`.
- Не добавлять сборщики, фреймворки, `package.json` и GitHub Actions — сайт статический и работает как есть.
- Не делать репозиторий приватным.
- Не запрашивать и не сохранять пароли и токены.
